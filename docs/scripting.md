# Orbita Scripting Language — полный справочник

**Контракт платформы:** каждая возможность ОС управляема из скриптов и
команд shell'а. Скрипт — текстовый файл (обычно `.sh`); каждая его
строка — команда того же встроенного shell'а, что доступен
интерактивно. Linux-совместимый синтаксис + расширенные Orbita-команды.

Живое доказательство в каждом буте: `sh /etc/demo.sh`
(маркеры `script: if ok`, `script: and-ok` в serial-логе, CI).

---

## 1. Запуск скриптов

| Способ | Пример | Поведение |
|---|---|---|
| `sh <путь>` / `bash` / `source` / `.` | `sh /etc/demo.sh` | исполнить файл |
| Относительный путь | `./demo.sh`, `../x.sh` | файл исполняется как скрипт |
| Абсолютный путь | `/etc/demo.sh` | то же |

Правила: вложенность скриптов ≤ 8; код возврата = `exit N` или статус
последней команды; шебанг (`#!/bin/sh`) игнорируется как комментарий.

## 2. Язык (управление потоком)

```sh
# комментарий
VAR=value              # присваивание (экспортируется сразу)
echo "$VAR and '$VAR'" # кавычки: "…" раскрывает $VAR, '…' — буквально

if test -f /etc/orbita.conf      # условие = любая команда (статус 0 = истина)
then
    echo found
elif test -d /etc
then
    echo dir
else
    echo missing
fi

for d in /etc /home "$EXTRA"     # слова с раскрытием $VAR
do
    test -d $d && echo "dir: $d"
done

while test -f /tmp/marker        # цикл, пока условие истинно
do
    rm /tmp/marker
done

break        # выйти из цикла (nesting-aware)
continue     # следующая итерация
exit 7       # закончить скрипт с кодом 7

cmd1 && cmd2     # cmd2 только при успехе cmd1
cmd1 || cmd2     # cmd2 только при неудаче cmd1
a | b | c        # пайпы (stdout → stdin)
out > file       # перезаписать; >> — дописать; < file — stdin
```

### `test` / `[ … ]` — условия
| Выражение | Истина, когда |
|---|---|
| `-z s` / `-n s` | s пусто / непусто |
| `a = b`, `a != b` | строки равны/не равны (`==` — синоним `=`) |
| `-eq -ne -lt -le -gt -ge` | целочисленное сравнение |
| `-f p` / `-d p` | путь — файл / каталог |
| `! expr` | отрицание |

### Арифметика `$(( … ))`
Целочисленные выражения (i64) с приоритетом операций и скобками:
`+ - * / %`, унарный минус, сравнения `< <= > >= == !=` (→ 0/1),
переменные `$VAR`/`${VAR}`/именем (отсутствующие = 0). Пробелы внутри
не важны; `<`/`>` внутри `$(( ))` — часть выражения, не редиректы.

```sh
i=0
while test $i -lt 3
do
    i=$((i + 1))          # счётный цикл
done
echo $(( (6 + 7) / 2 ))   # 6
echo $((3 < 4))           # 1
```

### Подстановка команд `$( … )`
Вывод команды встраивается в слово (концевые переводы строк
отбрасываются, многострочный вывод склеивается пробелами). Работает в
аргументах и присваиваниях; вложенность ≤ 4.

```sh
name=$(echo orbita)         # name=orbita
echo "host: $(uname)"       # подстановка в аргументе
files=$(ls /etc | wc)       # пайп внутри подстановки
```

### Ограничения v1 (честно)
Нет: функций, `case`, `until`, фонового `&`, подстановки внутри слов
`for`. Арифметика при делении на ноль / синтаксической ошибке остаётся
буквальным текстом. Циклы ≤ 10 000 итераций (защита от зависаний).
Ключевые слова (`if`, `then`, `do`, `done`, …) нельзя использовать как
имена команд.

## 3. Команды (полный список встроенного shell)

### Файловая система и навигация
| Команда | Описание |
|---|---|
| `ls [путь]` / `lsroot` | листинг каталога (корень) |
| `cd <путь>` / `pwd` | смена/печать рабочего каталога |
| `cat <файлы…>` | печать файлов (или stdin) |
| `write <путь> [текст]` | создать/перезаписать файл (текст или stdin) |
| `append <путь> [текст]` | дописать в файл |
| `touch <пути…>` | создать пустые файлы |
| `mkdir <пути…>` | создать каталоги |
| `rm <пути…>` | удалить |
| `mv <из> <в>` / `cp <из> <в>` | переместить/скопировать |
| `df` | статистика тома |

### Текстовые фильтры (пайпы)
`grep <шаблон>`, `wc`, `head [-n N]`, `tail [-n N]` — по stdin.

### Переменные и окружение
`VAR=value`, `echo`, `env`, `set`/`export VAR=value`, `history`,
`uname`, `meminfo`, `gpuinfo`, `true`, `false`, `test`/`[`.

### Приложения и пакеты
| Команда | Описание |
|---|---|
| `apps` | установленные приложения |
| `run <имя>` | запустить приложение (ring 3, syscall ABI v2) |
| `ps` | процессы |
| `launch <id>` | рабочий стол: активировать приложение |
| `pkg \| apt \| apt-get \| apk \| pacman \| dnf install/list/remove/update <…>` | пакетный менеджер |
| `which`/`type <имя>` | разрешение команды |

### Система и железо
| Команда | Описание |
|---|---|
| `services`, `svcrun` | сервисы и их статус |
| `events` | журнал событий |
| `desktop` | сессия рабочего стола |
| `netcfg` | сетевые интерфейсы (live-счётчики) |
| `ping <ip>` | ARP→ICMP ping |
| `motd` | сообщение дня |
| `clear` | очистить экран |
| `help` | справка |

## 4. Скриптуемость модулей (правило разработки)

**При добавлении любого модуля/подсистемы проверяй: можно ли всеми её
возможностями управлять командами shell'а и, значит, скриптами?**
Если нет — добавь команду (или подкоманду) в `orbita-shell/src/runtime.rs`
(`execute_command`) и:
1. задокументируй её в таблице выше;
2. покрой host-тестом логику команды;
3. если команда меняет состояние — дай и «читающую» команду для
   скриптов (`netcfg` читает, `pkg` пишет — обе в shell);
4. для long-running операций добавляй предсказуемый код возврата
   (`&&`/`||` в скриптах опираются на него).

Реализация языка: `orbita-shell/src/interp.rs` (интерпретатор,
9 host-тестов), `parser.rs` (`&&`/`||`, коннекторы), `runtime.rs`
(`test`/`[`, запуск скриптов по пути). Скрипты исполняются в ядре тем
же кодом, что и интерактивный ввод — нет второго синтаксиса.

## 5. Примеры

```sh
# /etc/demo.sh (исполняется при каждом буте)
for d in /etc /home /usr
do
  if test -d $d
  then
    echo "script dir: $d"
  fi
done
if test -f /etc/orbita.conf
then
  echo "script: if ok (config found)"
else
  echo "script: config missing"
fi
test -d /etc && echo "script: and-ok" || echo "script: and-fail"
```

```sh
# установка и проверка пакета, стоп при ошибке
pkg update && pkg install python3 || exit 1
pkg list | grep python
```
